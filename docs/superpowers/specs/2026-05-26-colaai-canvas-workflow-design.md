# ColaAI 创作工作流画布设计

## 目标

在 ColaAI 中实现一期完整可用的创作工作流画布。画布应成为独立的全屏创作空间，支持文本、图片和 AI 生图结果节点，并允许用户从图片或结果节点继续生成，让创作过程可以在画布中沉淀为可追踪的视觉链路。

## 范围

- 保留现有 `/ColaAI` 工作台入口和 `canvas` 模式。
- 将当前静态画布壳层升级为可交互画布。
- 支持文本节点、图片节点、AI 生图结果节点。
- 支持画布平移、缩放、节点拖拽、节点选中、节点删除。
- 支持从图片或结果节点继续生成，并把生成结果追加回画布。
- 使用浏览器本地持久化保存画布状态。
- 不新增后端画布项目 API。
- 不采用三栏常驻工作台布局。
- 不直接照搬 `infinite-canvas` 的暗色界面，而是复用当前项目已有浅色画布色调。

## 视觉与布局

画布保持当前 ColaAI 的浅色视觉基调：`#fafafa` 背景、淡紫色径向光晕、24px 细网格、白色玻璃节点卡片、紫色虚线连接。参考 `infinite-canvas` 的空间组织方式，但只借鉴沉浸式布局，不复制其暗色主题。

桌面端结构：

- 顶部轻量标题栏：返回按钮、画布标题和必要的状态入口。
- 中心全屏画布：承载节点、连线、网格和平移缩放视口。
- 底部悬浮工具条：手型工具、文本节点、图片节点、生成入口、上传入口、删除入口。
- 左下缩放控件：缩放比例、适配视图和基础帮助入口。
- 右下 AI 入口：在选中可生成节点时打开继续生成抽屉。
- 右侧抽屉或轻量弹层：只在需要编辑生成参数时出现，不常驻占用画布空间。

移动端优先保持可浏览和基础操作，复杂拖拽与多节点编排以桌面端体验为主。

## 组件设计

画布逻辑从 `cola-ai-workbench.tsx` 中的内联 `CanvasWorkspace` 拆出，放在 ColaAI 组件目录下，保持当前工作台入口不变。

- `CanvasWorkspace`：画布模式入口，装配顶栏、画布视口、工具条、缩放控件和生成抽屉。
- `InfiniteCanvasSurface`：负责画布平移、缩放、网格背景、节点层和连线层。
- `CanvasNode`：统一渲染文本、图片、结果三类节点，并处理选中态、拖拽、删除入口。
- `CanvasConnections`：渲染节点之间的紫色虚线连接。
- `CanvasToolbar`：底部悬浮工具条，提供新增节点、打开生成、删除等操作。
- `CanvasGenerationDrawer`：选中图片或结果节点后打开，复用当前生图参数和提交流程。
- `useCanvasStore`：管理节点、连接、视口、选中项、本地持久化和最近更新时间。

## 状态模型

一期只维护单个本地画布状态，避免引入后端项目管理复杂度。

```ts
type CanvasState = {
  title: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnectionData[];
  viewport: { x: number; y: number; zoom: number };
  selectedNodeId: string | null;
  updatedAt: string;
};

type CanvasNodeData = {
  id: string;
  type: "text" | "image" | "generation";
  position: { x: number; y: number };
  size: { width: number; height: number };
  title: string;
  content: string;
  imageUrl?: string;
  sourceTaskId?: string;
};

type CanvasConnectionData = {
  id: string;
  fromNodeId: string;
  toNodeId: string;
};
```

浏览器本地保存 key 使用项目命名风格，例如 `chatgpt2api:cola_canvas_state`。图片节点只保存已有图片 URL 或任务结果引用，不复制图片二进制，避免本地存储膨胀。

## 生成数据流

继续生成采用“节点作为参考输入”的轻量闭环。

1. 用户选中图片节点或 AI 生图结果节点。
2. 用户点击节点操作入口、底部生成入口或右下 AI 入口。
3. 打开 `CanvasGenerationDrawer`。
4. 抽屉内带入选中节点的图片引用，并复用当前项目已有提示词、比例、数量、模型等生图参数。
5. 提交生成请求时继续走现有生图 API。
6. 生成成功后，将新图片追加为 `generation` 节点。
7. 自动创建从原始节点到新结果节点的连接。
8. 画布本地状态立即保存。

手动连线不是一期阻塞项；一期的连接主要由继续生成流程自动创建，确保创作链路可追踪。

## 交互规则

- 拖拽画布空白区域时平移画布。
- 滚轮缩放画布，并限制最小和最大缩放比例。
- 点击节点时选中节点，显示轻量描边和操作入口。
- 拖拽节点时更新节点位置。
- 删除操作只删除当前选中节点，并移除相关连接。
- 新增文本节点时在当前视口中心创建默认文本节点。
- 导入图片节点时使用已有上传或图片引用能力，创建图片节点。
- 继续生成成功后，新结果节点出现在原节点右侧或当前视口可见区域，并自动选中。
- 返回 ColaAI 主工作台时不清空画布状态。

## 复用与边界

必须优先复用当前项目已有能力：

- 复用 ColaAI 工作台的 `canvas` 模式入口。
- 复用现有生图 API helper 和任务结果结构。
- 复用已有图片展示组件和认证图片处理逻辑。
- 复用当前画布壳层的浅色背景、网格、节点卡片和紫色连线视觉。
- 参考 `D:\IdeaProject\register\infinite-canvas` 的组件边界、store 分层、平移缩放和悬浮工具条思路。

不做以下事情：

- 不迁移参考项目的完整项目管理系统。
- 不引入后端画布存储。
- 不做暗色主题替换。
- 不做三栏常驻面板。
- 不把手动连线、框选、多选、复制粘贴、撤销重做作为一期必要交付。

## 测试与验证

自动测试沿用当前项目已有前端测试方式：`bun:test` + `renderToStaticMarkup`。测试应覆盖：

- ColaAI 画布模式仍渲染 `data-cola-panel="canvas-workspace"`。
- 画布渲染标题、网格、底部工具条、缩放控件和 AI 入口。
- 文本、图片、生成结果三类节点可渲染。
- 本地状态初始化能生成默认节点和视口。
- 选中可生成节点时，继续生成入口可见。
- 生成成功后的状态更新会追加结果节点并创建连接。

本地浏览器验证必须覆盖：

- 打开 `/ColaAI` 并进入画布模式。
- 新增文本节点。
- 新增或导入图片节点。
- 拖拽节点移动。
- 平移和缩放画布。
- 选中图片或结果节点并打开继续生成抽屉。
- 完成一次生成后，结果节点回填画布并自动连线。
- 刷新页面后本地画布状态仍保留。

## 验收标准

- 画布视觉与当前项目浅色 ColaAI 风格一致。
- 画布布局是全屏沉浸式，不出现三栏常驻面板。
- 用户可以完成“选中参考节点 → 继续生成 → 新结果进入画布 → 形成连接”的完整流程。
- 画布状态能在浏览器本地保存和恢复。
- 自动测试和本地浏览器验证均通过。
