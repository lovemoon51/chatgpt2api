# ColaAI 画布默认主页入口设计

## 目标

将 ColaAI 当前“点击画布直接进入编辑器”的体验调整为“先进入画布主页，再进入编辑器”。新的画布主页应参考 `https://infinite-canvas-cpco.onrender.com/canvas` 的信息架构思路，但视觉语言必须延续当前 ColaAI 的浅色、轻玻璃、内容导向风格，而不是复制参考站的深色产品库界面。

## 背景

当前 `web/src/app/ColaAI/components/cola-ai-workbench.tsx` 中，`mode === "canvas"` 会直接渲染 `CanvasWorkspace`。这让已有画布编辑器可以快速使用，但缺少一个稳定的画布落地页来承接以下行为：

- 返回继续编辑最近画布
- 从空白画布开始创作
- 从预设模板起步
- 在进入重交互编辑器前理解“画布”这一功能的定位

本次设计不推翻现有画布编辑器，而是在其前面增加一个主页层。

## 范围

- 保留现有 `/ColaAI` 页面和 `canvas` 主模式入口。
- 点击侧边栏或移动端主入口里的“画布”后，默认进入新的 `CanvasHome`。
- 用户从 `CanvasHome` 再进入现有 `CanvasWorkspace`。
- 编辑器左上返回行为从“返回发现页”改为“返回画布主页”。
- 主页支持三类进入动作：继续当前画布、新建空白画布、从本地模板启动。
- 主页展示本地画布摘要信息。
- 复用现有单画布本地存储，不在本期引入后端画布项目管理。

## 不在本期范围

- 不引入多画布列表或多项目管理。
- 不新增后端画布 API。
- 不实现远程模板市场。
- 不修改现有画布编辑器的核心节点、拖拽、缩放、生成链路模型。
- 不把 ColaAI 画布改造成参考站的暗色或 SaaS 控制台风格。

## 用户体验目标

- 点击“画布”后，用户先看到一个清晰、友好的创作入口页，而不是立刻掉入复杂编辑器。
- 已经用过画布的用户能一眼看到“继续当前画布”。
- 首次进入的用户能自然地开始第一张画布，且不会因为没有历史记录而看到空状态死角。
- 模板入口能降低“从哪里开始”的压力，但不把一期复杂度拖高。

## 信息架构

`canvas` 模式内部新增一个二级子视图：

```ts
type CanvasSubview = "home" | "editor";
```

模式关系保持为：

- `ColaAIWorkbench` 仍然负责 `mode === "canvas"` 的总入口
- `canvas` 模式内部根据 `CanvasSubview` 决定显示 `CanvasHome` 还是 `CanvasWorkspace`

主流程如下：

1. 用户点击侧边栏“画布”
2. `mode` 进入 `canvas`
3. 默认 `CanvasSubview` 为 `home`
4. 用户在 `CanvasHome` 执行以下任一操作：
   - 继续当前画布
   - 新建空白画布
   - 选择模板
5. 系统切换到 `CanvasSubview = "editor"`，进入 `CanvasWorkspace`
6. 用户在编辑器点击返回时，回到 `CanvasHome`

## 页面结构

### CanvasHome

`CanvasHome` 是 ColaAI 工作台中的一个主内容页，而不是全新独立站点。它沿用现有 ColaAI 页面框架和侧边导航，只替换当前主内容区。

建议结构：

1. 顶部 Hero 区
   - 标题：强调从一张画布开始组织创意
   - 副标题：强调参考图、提示词、生成结果可以留在同一条创作链路中
   - 轻量说明文案：帮助用户理解画布区别于普通生图页

2. 主行动区
   - `继续当前画布` 主卡
   - `新建空白画布` 主卡

3. 模板区
   - 3 到 4 个本地预设模板卡
   - 每个模板包含名称、简短说明、轻量视觉区块

4. 最近摘要区
   - 显示当前本地画布标题
   - 最近更新时间
   - 节点数量
   - 是否有生成链路内容

如果本地没有历史画布，则：

- `继续当前画布` 卡片改为“还没有画布”
- 主按钮改为“创建第一张画布”
- 最近摘要区显示引导文案而不是错误状态

### CanvasWorkspace

现有 `CanvasWorkspace` 主体保留，仅调整入口和返回逻辑：

- `onBack` 由返回 `discover` 改成返回 `CanvasHome`
- 编辑器不再是 `canvas` 模式的默认首屏

## 视觉设计

主页视觉必须从当前 ColaAI 风格自然延伸，不照搬参考站的深色产品化界面。

视觉原则：

- 背景保持浅暖白和轻氛围层
- 允许复用现有 `RovaMediaBackground` 的空间感，但透明度更轻，减少干扰
- 卡片使用现有项目中的白玻璃、浅边框、轻阴影、圆角语言
- 点缀色优先使用 `sky / emerald / amber`，避免把首页做成紫色主导
- 与现有画布编辑器相比，主页减少网格密度和“工具态”压迫感

布局原则：

- 桌面端采用上 Hero、下卡片区的内容型结构
- 移动端改为单列纵向堆叠
- 不做复杂悬浮侧栏或三栏编排
- 重要动作优先级为：继续当前画布 > 新建空白画布 > 模板启动

## 数据模型与状态

本期继续使用现有单画布本地状态，不扩展为多画布集合。

现有存储：

- `chatgpt2api:cola_canvas_state`

新增主页所需数据不单独创建复杂持久化结构，而是从现有画布状态推导轻量摘要：

```ts
type CanvasHomeSummary = {
  hasCanvas: boolean;
  title: string;
  updatedAt: string | null;
  nodeCount: number;
  hasGenerativeContent: boolean;
};
```

推导规则：

- `hasCanvas`: 节点或连接存在，或标题不是默认空白引导值
- `title`: 来自现有 `CanvasState.title`
- `updatedAt`: 来自现有 `CanvasState.updatedAt`
- `nodeCount`: `state.nodes.length`
- `hasGenerativeContent`: 是否存在 `generation`、`image` 或带图片结果的节点

如果本地状态解析失败、损坏或不可用：

- `CanvasHomeSummary` 回退为空状态
- 页面继续可用，不显示异常崩溃状态

## 入口动作定义

### 继续当前画布

行为：

- 如果存在可用本地画布状态，直接进入 `CanvasWorkspace`
- 如果不存在可用状态，则行为等同于“创建第一张画布”

用户可见反馈：

- 有历史时显示标题、更新时间和节点数
- 无历史时显示空状态引导

### 新建空白画布

行为：

- 清空当前本地画布状态
- 用现有默认初始化逻辑创建一张新的空白起步画布
- 进入 `CanvasWorkspace`

要求：

- 不依赖后端
- 初始化失败时回退到当前默认初始化画布

### 模板启动

行为：

- 使用本地模板预设生成初始节点结构
- 保存为当前本地单画布状态
- 进入 `CanvasWorkspace`

一期模板来源：

- 本地常量模板，不做网络请求

建议模板：

- 品牌情绪板
- 海报概念板
- 产品视觉拼贴
- 分镜草图

模板节点可由现有节点类型组合而成，例如：

- 文本节点：主题说明
- 图片节点：参考位
- 配置节点：生成参数说明
- 生成结果节点：输出目标位

## 组件边界

建议新增或调整以下边界：

- `CanvasHome`
  - 负责主页 hero、主卡、模板区、摘要区
- `canvas-home-state.ts`
  - 从现有画布状态推导主页摘要
  - 提供空白画布和模板画布的初始化 helper
- `CanvasWorkspace`
  - 保持现有编辑器主体
  - 调整返回行为
- `ColaAIWorkbench`
  - 负责 `canvas` 模式下的 `home | editor` 子视图切换

这样可以避免把主页判断逻辑塞回大型工作台组件，同时为以后升级多画布能力保留扩展点。

## 交互规则

- 点击侧边栏“画布”总是进入 `CanvasHome`
- `CanvasHome` 中任一主动作都进入编辑器
- 编辑器返回按钮回到 `CanvasHome`
- 刷新页面时，如果仍处于 `/ColaAI`，工作台默认模式规则不变，但用户再次进入 `canvas` 时依旧先看到 `CanvasHome`
- 主页卡片和模板在移动端保持可点击大触区
- 空状态文案不应显得像错误，只应像首次引导

## 错误处理

- 本地存储读取失败：按无历史画布处理
- 模板初始化异常：回退为空白画布并进入编辑器
- 历史状态缺字段：使用默认值兜底，不中断进入流程
- 浏览器不支持本地存储：主页仍可展示，编辑器退化为会话内状态

## 测试与验证

自动测试应覆盖：

- `ColaAIWorkbench` 在 `canvas` 模式下默认渲染 `CanvasHome`
- `CanvasWorkspace` 不再是 `canvas` 模式的默认首屏
- 有历史摘要时显示“继续当前画布”
- 无历史摘要时显示“创建第一张画布”
- 模板卡片存在且可触发进入编辑器
- 编辑器返回后回到 `CanvasHome`

浏览器验证应覆盖：

- 进入 `/ColaAI`，点击“画布”后先看到主页
- 点击“继续当前画布”进入编辑器
- 点击“新建空白画布”进入新编辑器状态
- 点击任一模板后进入带初始节点的编辑器
- 在编辑器返回后重新回到主页
- 刷新页面后主页摘要仍能读出最近状态

## 验收标准

- 点击 ColaAI 的“画布”后默认进入主页，而不是直接进入编辑器
- 新主页视觉与当前 ColaAI 保持一致，不出现明显风格断层
- 用户可以从主页完成继续、新建、模板启动三类进入动作
- 编辑器仍保持现有核心功能可用
- 编辑器返回行为正确回到主页
- 自动测试和本地浏览器验证通过

## 后续扩展方向

本设计故意为未来多画布能力留出空间。后续如果需要升级，可以在不推翻当前主页结构的情况下扩展为：

- 多画布草稿列表
- 画布缩略图
- 最近访问画布
- 复制与删除草稿
- 云端画布项目同步
